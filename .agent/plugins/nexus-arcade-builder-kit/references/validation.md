# Evidence boundaries

Use PASS only for an executed check against the exact candidate. FAIL records an executed mismatch. BLOCKED records a missing environment, permission or dependency. NOT RUN records absent coverage.

Required coverage is proportional to the game and actual changes: source/build parity, manifest identity, rule outcomes, controls, lifecycle, pause, hidden-tab recovery, repeated restart, disposal, resource bounds, storage corruption/denial, asset/audio failure, responsive presentation and real player path. Add game-specific edge cases such as route commitment and rear clearance rather than relying on generic smoke alone.

The read-only inspector reports hashes and package facts. It cannot establish playable behavior, quality, novelty, rights or release approval. Actual browser checks and physical target-device checks are separate. Keep explicit failed attempts if they explain why coverage is missing.

For reuse, source comparison can reject an unsuitable abstraction. It cannot prove runtime parity. Require executable consumer fixtures before extracting a shared implementation.
