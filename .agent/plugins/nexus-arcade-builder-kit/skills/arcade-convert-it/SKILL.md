# arcade-convert-it

Recover the existing game identity, approved fantasy, mechanics, controls and prior artifact. Preserve the incoming source/hash and inspect dependencies before execution. If an input or pin is missing, state it and continue independent inspection.

Read ../../references/workflow.md and the current conversion guide. Establish a before-state and a subsystem decision matrix. Inspect actual Engine exports at the consumer pin and existing optional Kits; a domain name or migration placeholder is not implementation evidence. Use arcade-reuse-audit-it for shared-system candidates.

Implement a playable slice, then expand within scope. Keep authored maps, balance, visuals and genre rules game-owned. Use genuine Engine services rather than adding an unused import. Preserve the game fantasy through substantive decisions and feedback; do not silently replace mechanics to meet a conflicting standard.

Use games/<slug>/source, build and install metadata. Protect other games from global build churn. Run arcade-validate-it and retain unproven device/browser gates. Integration and release need their respective authorization. Provide the exact candidate, behavior changes, reuse findings, validation and next action.
